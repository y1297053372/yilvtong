## 一、必须改（会被当场问住）

### 1. 衣律通时间线错误

**现在写的**：

> 衣律通　服装购物维权微信小程序　**2025.01 - 2025.02**　|　独立推进并上线

**问题**：你是 2025 级本科。2025 年 1–2 月你还没入学。这个日期经不起任何追问。

代码文件的实际修改时间分布：

| 月份 | 文件数 |
|---|---|
| 2026-01 | 39 |
| 2026-02 | 108 |
| 2026-03 | 56 |

**建议改成**：`2026.01 - 2026.03`

这正好是大一下学期跨寒假，与项目体量（21,833 行、17 页、4 云函数）匹配，也解释得通为什么两个月能从零做到上线。

### 2. "独立推进"与团队口径冲突

**现在写的**：

> 独立推进需求分析、产品设计、测试与上线

**问题**：商业计划书 `7.1.2` 明确写着团队 5 人，你是**技术负责人**：

> 技术负责人：言子仪，本科25级通信工程专业……他主导"衣律通"小程序的整体架构与核心功能开发

两处说法打架。评审若同时看到简历和计划书，第一反应是"哪个是真的"。

**建议改成**：

> 技术负责人｜主导技术架构与全部小程序实现，协调 4 人团队完成产品、财务与内容模块

大一做到 5 人团队的技术负责人，比"一个人全干"更有说服力——前者证明协作能力，后者在评审眼里往往意味着"其他人没干活"。

## 二、建议改（表述可更准确）

### 3. "17 个页面"是对的，但可以更完整

现在写"实现 17 个页面及后端数据存储与查询"，与 `app.json` 一致（17 个已注册页面）。

可补：`5 个组件 + 4 个云函数 + 21,833 行代码`。数字具体，且可验证。

### 4. "参加全国大学生电子商务'创新、创意及创业'挑战赛"

这句是事实，但没说结果。如果没获奖，建议改成"以该项目参赛"或直接删掉——列一个没有结果的比赛，不如把篇幅让给技术细节。

如果进了省赛/国赛，那一定要写出来。

### 5. 云开发配额到期这句现在放在简历里

**现在写的**：

> 说明：微信云开发后端配额已到期，部分文章与图片暂无法加载。

**问题**：在简历里主动交代缺点，位置不对。简历是"我做了什么"，限制条件应该放在项目报告或 GitHub README 里（我已经写在 README 的「已知限制」章节）。

**建议**：从简历删掉这句。如果面试被问到"能跑吗"，口头解释 + 展示 GitHub 仓库和报告即可，这反而是加分项（说明你诚实且清楚自己的系统状态）。

### 6. "借助 Trae IDE 和智谱 GLM 完成开发"

**问题**：代码里 AI 能力用的是**腾讯混元**（`aiService.js` 中 `hunyuan-turbos-latest`），不是智谱 GLM。GLM 可能只是你开发时用的辅助模型，但这句话读起来像"产品依赖 GLM"。

**建议改成**：

> 借助 Trae IDE 辅助开发；产品内 AI 能力接入腾讯混元（流式输出）

区分"开发工具用的 AI"和"产品集成的 AI"，这是个容易被问住的技术细节。
