# 衣律通

服装网购维权微信小程序。用户在五步引导表单里描述纠纷，程序生成符合司法格式的**民事起诉状 / 举报信 / 协商函**，并给出针对该侵权情形的取证清单。

> 技术负责人：言子仪　|　开发周期：2026.01 – 2026.03　|　微信小程序 + 云开发

---

## 这个项目解决什么问题

一件 200 元的衣服货不对板，打官司的成本远高于标的额，找律师更不划算。消费者卡在中间：知道该维权，不知道怎么下笔。

法律文书的门槛不在"想不想写"，而在三件具体的事——**格式对不对、事实怎么组织、法条引哪一条**。衣律通把这三件事拆成结构化表单，用户填的是生活语言（"收到货发现面料和页面写的完全不一样"），程序输出的是法院能收的文书。

同时针对每类侵权情形给出**该拍什么、怎么拍、拍几张**的取证清单。这是整个产品里最容易被低估的部分：败诉往往不是因为没理，而是因为证据不成链。

## 三个值得讲的技术点

### 1. 用模板方法基类消掉三个表单页的重复

三种文书（起诉状 / 举报信 / 协商函）流程高度相似：五步向导、逐步校验、草稿自动保存、免责声明、PDF 导出。如果各写一遍，是三份 800 行上下的近似代码。

`utils/baseFormPage.js`（789 行）用模板方法模式抽出骨架：

- **抽象方法**用 `throw new Error` 强制子类实现（`getDocumentType` / `generateDocumentTitle` / `generate` / `validateStep`）
- **钩子方法**提供可选扩展点（`onDraftLoaded` / `onStepChange` / `getExtraDraftData`）
- 子类只写有业务差异的部分

结果：三个表单页合计约 2,300 行，其中基类承担了通用逻辑。`report-detail.js` 只需 67 行、`negotiation-detail.js` 只需 29 行，因为派生页面的差异被压缩到了覆写几个方法。

### 2. AI 生成的部分不是"让模型随便写"

直接把用户输入丢给大模型，输出会有标题、有落款、有 Markdown、有"综上所述，恳请贵院…"的套话——这些都必须由系统统一控制，否则格式会崩。

`utils/aiService.js`（120 行）做两件事：

**约束 Prompt**，六条硬规则：禁止输出标题、禁止生成落款、禁止 Markdown、禁止重复结尾句、必须引用具体法条、必须按"交易背景 / 侵权事实 / 法律依据"分段。

**后处理清洗**。模型不会 100% 听话，所以 `cleanAIText()` 再兜一层：剥掉 `**` 和 `##`，去掉可能跑出来的标题行，在"此致""具状人""综上所述"处截断，并移除模型自己生成的"故原告…"句——这部分由系统按标准格式拼接。

流式输出（`streamText` + `for await`）让用户边生成边看到文字，等待感明显下降。

### 3. 法院推荐：一个被过滤函数救回来的功能

用户通常不知道该去哪个法院起诉。`cloudfunctions/searchCourts` 走腾讯地图 POI 检索，关键词"人民法院"，限定 `category:130502`。

问题在于 POI 数据里混着大量非法院机构：法院旧址、法院家属院、法院宿舍、隔壁的打印店。初版直接返回，用户看到一堆"XX区人民法院旧址"。

解法是 45 个关键词的黑名单 + 名称长度排序（本级法院名称通常最短）+ 多级兜底（API 失败时按行政区划拼出标准的"XX市XX区人民法院"）。这一步让功能从"能返回结果"变成"能返回正确结果"。

## 合规改造：提审被驳回之后

这是项目里最曲折的一段，也是最能说明工程能力的地方。

**第一次提审被驳回**，理由是「小程序涉及收集、存储用户身份信息，平台暂不支持此功能」。

原因：起诉状必须填写当事人姓名、身份证号、住址。微信对身份证号这类敏感个人信息管得极严——`《微信小程序平台运营规范》15.1.3` 要求除非法律要求或经用户同意，否则不得要求用户输入个人信息才可使用功能；而《个人信息保护法》把身份证号列为敏感个人信息，需要单独、明示、自愿的同意。

做了四件事：

1. **把身份证号改成可选**。不填也能生成文书，法院立案时可补
2. **收集前弹窗单独告知**，说明用途、范围、存储方式、用户权利，不默认勾选
3. **脱敏展示**：`maskIdCard()` 只显示首位和末位，其余打码
4. **加密存储**：`encryptData` 云函数处理敏感字段后再落库

`utils/privacyUtils.js`（210 行）把这些能力收成公共模块，三个表单页共用。

这段经历的价值在于：它逼着我去读平台规范和个保法，理解"合规"不是加个弹窗，而是重新设计数据的最小化采集边界。

## 如何运行

1. 微信开发者工具导入本目录（`project.config.json` 已指向 `miniprogram/`）
2. 填入自己的 AppID，开通云开发环境
3. 修改 `miniprogram/app.js` 中 `wx.cloud.init({ env: '...' })` 为你的环境 ID
4. 修改 `miniprogram/config/constants.js` 的 `CLOUD_ID_PREFIX` 与 `CLOUD_ENV_ID`
5. 建 `article` / `documents` / `user` / `comments` 四个集合，`数据库/` 下的 JSONL 可直接导入 `article`
6. 上传四个云函数，`searchCourts` 需在环境变量配置 `MAP_KEY`（腾讯地图 Key）
7. `generateDocumentPDF` 依赖 `pdfkit`，上传前在云函数目录执行 `npm install`

## 关于数据库导出

`数据库/` 下的文件是云数据库的真实导出，用于展示数据结构与知识库内容（59 篇文章、4 大类三级分类）。

**已脱敏**：4 个真实 openid、3 个用户昵称、OpenID 派生的数字 ID 全部替换为占位符，共 587 处。脱敏后 JSONL 仍可正常解析。
